# 実装構造に対する懸念の例

本実装は、ECS構造に柔軟で相互作用可能なFSMを導入することを目的として行われいてる<br>
その試みは現在のプロジェクトでは正常に動作していることが確認されいている<br>
しかし、この実装がこのポートフォリオ内の文脈に依存しすぎているという懸念がある<br>

そこで、ここではこの実装の依存構造の抽象境界を考える

行うべきことの例を以下に挙げる

## 1. 依存構造の抽象境界はどこにあるか？
- AoS / SoAの違いを超えて共通化できる最小の抽象を特定する


## 2. 性能ボトルネックが発生しそうな箇所はどこか？
- Lease管理・干渉解決・Effect発火の3つを局所ベンチで計測する


## 3. このモデルを他の文脈(AI/Animation専用)に再利用できるか?
- "FSM x Lease"の仕組みをサブドメインで試してみる
